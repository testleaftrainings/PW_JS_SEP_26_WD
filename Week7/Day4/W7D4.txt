Five Steps process for API testing
------------------------------------

1. Documentation
: Understanding the API's purpose, structure, and usage guidelines before testing.
Example: 
: Reading Swagger docs that describe how the incident API works in an application.

2. Endpoints: 
: Specific URLs that represent resources or actions to be tested.
Example: 
:https://hostname/services/oauth2/token

3. Methods: 
: HTTP operations (GET, POST, PATCH, PUT, DELETE, etc.) that define the type of action on the 
resource.
Example: 
: GET /incident → fetch incidents; POST /incident → create a new incident.

4. Headers: 
: Metadata sent with requests or responses to control and describe API behavior.
Example: 
Content-Type: application/json, Accept: application/json.

5. Authorization: 
: Security mechanism to verify and allow only valid users or systems to access the API.
Example: 
Authorization: Bearer <token> or Basic Auth with username & password.

Together, these 5 steps ensure your API test covers what, where, how, and who can access the service.
********************************************************************************************
OAuth 2.0 (Open Authorization) is an authorization framework where an Authorization Server 
generates access tokens to allow clients to securely access protected resources.

HTTP Methods:
-------------

1) Generate Access Token
Authenticate user and receive access token.

2) Use Token in Authorization
Pass token as Bearer token in request header.

3) Create Resource
Use POST method to create new record.

4) Get Resource
Use GET method to fetch existing record.

5) Update Resource
Use PATCH/PUT method to modify record.

6) Delete Resource
Use DELETE method to remove record.

Steps to find the field in salesforce :
----------------------------------------

From Salesforce Setup (Recommended)

Log in to your Salesforce Developer Org.

Go to Setup → Object Manager.

Search for and click on Lead.

Open Fields & Relationships.

You will see a list of all the fields available on the Lead object.

The Field Label is what you see in the UI (e.g., “Last Name”).

The Field Name is what you use in the API (e.g., LastName, Company).

These “Field Names” are what you should use in your JSON request body.

Playwright with API:
--------------------

Request fixture:  Built-in fixture used for API testing in Playwright. It provides request context 
to send HTTP requests and validate responses inside Playwright test cases.

we can get the context information without launching the browser.

APIRequestContext: used to create an isolated API session for sending HTTP requests directly to 
backend services. It helps us perform API testing, create test data, validate responses, handle 
authentication, and combine API testing with UI automation workflows without opening browser.
